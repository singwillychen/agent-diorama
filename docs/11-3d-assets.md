# 11 · 3D 素材策略

## 現階段：程式生成（由 Claude 直接寫出）

MVP 的所有 3D 物件都是 **程式生成**（procedural），不依賴任何外部模型檔：

| 物件 | 位置 |
|---|---|
| 浮空山峰、雲海、松樹、仙鶴、遠山 | `web/src/scene/xianxia/terrain.tsx` |
| 大殿（重簷）、藏經閣、煉丹爐、牌坊、傳送陣、護山大陣、洞府 | `web/src/scene/xianxia/buildings.tsx` |
| Q 版修士角色（約 3 頭身、表情、動作、職能道具） | `web/src/scene/xianxia/Character.tsx` |

優點：零授權風險、檔案極小、可依資料即時改色與比例（境界光環、門派配色），而且每個 agent 都能用參數做出差異。

限制：「寫實派」質感只能做到 **PBR 材質 + 柔和光影 + 移軸微縮** 這一層，細緻布料皺褶、髮絲與臉部雕刻要靠真正的模型。

## 下一階段：替換成高品質模型

資產契約已定義在 [07-extensibility.md](07-extensibility.md#6-資產契約asset-contract)。只要符合命名與骨架規範的 GLB，就能直接替換程式生成的版本。

### 建議工具

| 用途 | 建議 | 說明 |
|---|---|---|
| 角色模型 | **Tripo**、**Meshy**、**Rodin（Hyper3D）** 這類專門的 image/text-to-3D 工具 | 先用圖像模型畫出統一風格的角色三視圖，再轉 3D；輸出 GLB + PBR 貼圖 |
| 角色綁骨與動作 | Mixamo、AccuRIG | 自動綁定 Humanoid 骨架，套用待機、走路、坐、舉手等動作 |
| 場景建築 | Blender 手工修整，或由 AI 生成後拆件 | 錨點（`zone:*`、`seat:*`）在 Blender 以空物件標註 |
| 概念圖 / 三視圖 | 圖像生成模型 | 先鎖定畫風，再大量產出角色變體 |

### 關於 Claude 與其他模型的分工

- **Claude（含 Opus 5.5）擅長的是寫程式、場景邏輯、程式生成幾何與 shader**，但不會直接輸出貼圖精細的網格模型檔。所以「用 Claude 做 3D 素材」最適合的形式，就是目前這種程式生成的方式。
- 你提到的「GPT 的 astra」我無法確認是哪個產品，所以沒辦法比較。如果目的是做出寫實質感的 3D 角色，通常是 **圖像模型畫概念圖 + 專門的 3D 生成工具轉模型** 效果最好；決定前可以拿同一張角色設定圖給兩三套工具各跑一次再比較。
- 建議流程：Claude 寫程式與規格 → 圖像模型畫概念圖 → 3D 生成工具出模 → Blender 修整、綁骨 → 依資產契約匯出 GLB → 放進 `assets/` 替換程式生成版本。
